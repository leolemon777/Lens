## 0. 基线与决策

### 0.1 当前仓库事实

`Package.swift` 当前仅声明 macOS 15，产品是 `LensCore` 和 `LensMac`。`Sources/LensMac` 依赖 AppKit、SwiftUI、ScreenCaptureKit、AVFoundation、Vision/Speech，不能在 Windows 上直接构建为可用应用。

`Sources/LensCore` 已提供项目 schema、事件、时间线、运镜、字幕和整理规则，是行为规范与黄金测试来源，不等于已经具备 Windows 可执行核心。`CoreWorkerRuntime.swift` 当前提供 Swift 握手与回退路由，不是已实现的 Rust 运算服务。现有 CI 主要运行于 macOS；Windows 构建、捕获、安装和硬件测试需要新增。

当前仓库已包含 Windows 工具链锁定、Rust worker、native 捕获/编码、截图/录屏基础闭环、internal unpackaged 制品和可重复验收脚本；签名安装器、升级/回滚、完整编辑器及 W3–W6 能力仍属于计划范围。本文中的未完成项必须以 `docs/windows/执行记录.md` 的实测状态为准，不得把 internal 制品宣传为完整 Windows 版本。

### 0.2 产品及技术选择

| 项目 | 规划决定 | 冻结条件 |
|---|---|---|
| 正式支持 | Windows 11 x64；候选最低 24H2，发布时仅承诺仍受支持且完成测试的版本 | W0 锁定具体系统版本、SDK 和运行器镜像 |
| 其他系统 | ARM64 为后续独立构建；Windows 10、Server、Wine 不进入首版支持承诺 | 不以模拟运行代替原生验收 |
| 应用界面 | React + TypeScript + Vite，由 Tauri 2（Rust）承载；托盘及捕获浮层通过 Tauri/Win32 集成，WebView2 渲染 | M0 完成多屏浮层、打包外部署和焦点原型 |
| 捕获与渲染 | Rust + `windows` crate：Windows Graphics Capture、D3D11、Media Foundation、WASAPI；二维图形与文字引擎在 M0 冻结 | M0 验证纹理到编码链路、字体和媒体格式 |
| 共享规则 | 业务后端与平台调度迁入 Rust；`lens-worker` 保留并扩展，以 Swift 黄金结果作为基准 | 每项能力通过一致性测试后才启用 |
| 进程通信 | 首版使用受控子进程 stdio 长度前缀 JSON；named pipe 后续按实际需要实现 | 不把传输升级作为首版前置条件 |
| 发布形态 | 支持自选安装目录的签名 EXE 安装器，部署 unpackaged 应用；MSIX/商店后续 | W0 验证运行时部署、应用身份需求和无管理员安装 |
| 本地智能 | OCR 和转写均用可替换本地引擎；不依赖特定 NPU，也不默认使用云端 | W0 验证许可证、中文/英文、离线和模型体积 |

这些是本项目选择，非 Microsoft 对最低系统或实现方式的强制要求。工具链采用冻结时受支持的稳定版本，将具体版本、锁文件和来源写进构建文档，避免使用浮动 latest。

## 1. 用户目标与版本范围

首屏直接进入可用的截图/录屏操作中心，不要求登录。托盘常驻默认可用，开机启动由用户主动开启。目标用户为日常截图沟通、制作产品演示和教程、需要离线保存素材的人。

| 能力 | W2 内测 | Windows 1.0 必须完成 | 1.x 后续 |
|---|---|---|---|
| 截图 | 区域、窗口、显示器，复制、PNG、历史 | 多窗口、长截图、贴图、九类对象标注、样式、PNG/JPEG | 更多识别与批量操作 |
| 录屏 | 区域/窗口/显示器，30 FPS，系统声/麦克风、暂停恢复 | 30/60 FPS、摄像头分轨、事件轨、可靠恢复 | 单应用音频、更多专业采集 |
| 自动成片 | 保留原始视频，可生成基础草稿 | 运镜、光标、点击、画布、画中画、混音、字幕 | 高级生成式编辑 |
| 编辑导出 | 原始 MP4 可播放和导出 | 裁切、分割、重排、变速、转场、关键帧、视频标注、三档导出 | 重型多轨编辑不在当前承诺内 |
| 检索与智能 | 标题、时间、类型 | 中英离线 OCR/转写、摘要/标签/章节、人工校正、本地统一搜索 | 更多语言与语义检索 |
| 分发维护 | 内部构建、故障报告 | 签名安装、升级/回滚、卸载保留素材、完整使用指南 | 商店和 ARM64 |

W2 只能称“内测可用版”，不得宣传与 macOS 功能等价。Windows 1.0 必须完成本表全部首版项；缩减范围需要更新本规格和发布说明，不能只隐藏未完成控件。

## 2. 安装与日常使用规格

### 2.1 安装、首次启动与 E 盘存储

1. 用户运行签名安装器，可选择例如 `E:\Apps\Lens`；先校验系统、架构、磁盘与运行时，再安装，失败不得留下可启动的半成品。
2. 首次启动显示项目库目录选择器和实际可用空间。本机建议 `E:\LensData`，不要把真实录屏放入源码仓库。
3. 缓存、模型和临时媒体也可选到 `E:\LensCache`、`E:\LensModels`。大文件处理必须使用配置目录，不能偷偷回退系统临时盘。
4. 桌面快捷方式通过 Windows Known Folder API 定位实际桌面；本机当前为 `E:\Users\Administrator\Desktop`，不能写死 `C:\Users\...\Desktop`。
5. 首次只配置截图与操作中心热键、目录；麦克风、摄像头、模型下载在使用时提示。默认摄像头关闭，音频开关在录制前明确显示并记忆用户选择。
6. 操作中心提供一次真实截图和短录屏验证；权限取消、设备不可用、写盘失败均显示可操作原因。

“主体放 E 盘”不承诺 Windows 完全零写入 C 盘：少量设置、系统运行时、安装登记及系统诊断可能仍在系统目录。应用必须列出数据位置；项目、模型、媒体缓存不得未经确认更换到 C 盘。E 盘掉线时停止新捕获并允许重新选择目录，不自动创建另一套空库。

### 2.2 快捷键与托盘

候选默认 `Ctrl+Alt+1` 截图，`Ctrl+Alt+2` 操作中心；录制中第二组打开控制条。支持自定义和冲突检测；注册失败时保留托盘入口并要求选择新组合，不抢占系统截图键。必须测试 AltGr、中文输入法、全屏应用及管理员窗口；普通权限运行，不以全程管理员启动规避限制。

托盘菜单包含截图、录屏、素材库、设置、退出。退出时有录制必须先安全停止；处理中任务可取消并保存恢复标记。Esc 取消选区/关闭浮层，Enter 确认；Ctrl+C、Ctrl+Z、Ctrl+Shift+Z 遵循 Windows 习惯。

### 2.3 截图闭环

热键 → 选区/窗口/显示器 → 原图原子落盘 → 剪贴板 → Quick Access → 复制、拖出、标注、贴图 → 入库。剪贴板被占用时限次重试，失败仍保留文件和复制重试入口，不能把“截图成功”等同于“粘贴成功”。

窗口选取排除 Lens 浮层；跨屏、负坐标、混合 DPI、窗口边框与阴影具有一致规则。多窗口按选定层级合成；关闭或受保护的窗口明确失败，不静默改拍整个屏幕。长截图由用户滚动驱动，保留源帧和拼接计划；遇动画、重复区域或无重叠时暂停并允许结束，不持续拼接错误内容。

贴图支持置顶、拖动、缩放、透明度、锁定、复制及关闭。标注包括矩形、椭圆、箭头、画笔、高亮、编号、文字、模糊、像素化，均可编辑和撤销；遮挡效果必须进入实际导出像素。复制透明图同时验证 DIB/PNG 等格式在常见目标应用中的行为。

### 2.4 录屏闭环

选择来源 → 确认系统声/麦克风/摄像头及电平 → 倒计时 → 录制/暂停/继续 → 安全停止 → 原始素材立即可播放 → 异步生成草稿 → 编辑导出。

控制条显示时长、状态、电平、磁盘空间；暂停时间不进入媒体或事件时间轴。麦克风和摄像头独立保存，系统声保留独立资产或可独立解复用的轨道，不提前混入旁白。系统声默认明确为所选输出设备的混音，不能把窗口录制宣传为仅该窗口声音。

锁屏、休眠、显示器断开或来源窗口关闭默认安全停止；恢复桌面后由用户重新开始。切换音频设备采用分片边界重建并写入不连续信息，无法恢复时提示并保留已录内容。丢弃并重录需确认，先完成停止，移入回收站成功后才重录。

### 2.5 编辑、检索与分享

编辑器采用素材预览、时间线、属性区；支持上述首版编辑项、撤销重做、未保存防护、后台任务进度与取消。预览和导出消费同一规范化渲染计划。系统字体差异允许有限像素差异，但构图、时码、可见效果与音轨不能缺失。

素材库按时间浏览，按类型/标签筛选，并搜索标题、OCR、转写和整理结果。离线模型缺失时截图录屏仍可用，智能任务显示待准备；模型下载须先展示体积、许可证和保存位置，支持中断恢复与摘要校验。首版不默认上传素材。

导出支持 PNG/JPEG、H.264 MP4；原画/平衡/轻量有明确帧率、分辨率、码率/质量意图。HEVC 为探测后可选，缺少编码器时允许明确选择 H.264 回退并记录实际设置，不声称生成了 HEVC。首次分享只提供本地文件、复制和资源管理器定位。

## 3. 架构与代码边界

### 3.1 拟新增工程

目标工程结构（v2.0，详细所有权以 CODE PLAN 为准）：

```text
Desktop/                         # React + TypeScript + Vite 前端
  src/app/、components/、styles/
  src/features/、bridge/
  tests/
Desktop/src-tauri/               # Tauri 2 应用 crate（Rust）
  src/、capabilities/、permissions/
CoreRust/
  Cargo.toml、Cargo.lock、rust-toolchain.toml
  crates/lens-core/              # 纯数据规则与协议
  crates/lens-project/           # 文件、索引、锁、schema 迁移
  crates/lens-platform-windows/  # OS 资源、设备、Windows API
  crates/lens-media/             # 管线、时间、合成、播放、导出
  crates/lens-analysis/          # 模型、OCR/转写、整理、队列
  crates/lens-worker/            # 受控子进程任务入口
Scripts/windows/                 # 环境、构建、测试、打包、验包
docs/windows/                    # 安装指南、兼容矩阵、证据、回滚手册
```

React 承载操作界面与交互草稿；Tauri/Rust 持有业务真相、权限与系统资源；平台 crate 拥有设备、GPU 纹理和编码器。React 与 Rust 使用类型化 commands/事件边界，原始视频帧不逐帧 JSON/base64 传给前端。旧 `Windows/` C#/C++ 工程已删除，默认构建只走 `Desktop/` + `CoreRust/`。

核心业务接口至少包含 `CaptureService`、`AudioCaptureService`、`RecordingSession`、`ProjectRepository`、`CoreWorkerClient`、`RenderService`、`LocalAnalysisService`。每个接口约定异步取消、超时、关闭幂等、状态事件及稳定错误，UI 不直接操作媒体线程。

### 3.3 Worker 与能力降级

沿用协议 v1 的 4 字节大端长度、1 MiB 帧限额、requestID、能力协商与稳定错误码。首先复用 `Tests/LensCoreTests/Fixtures/core-worker-protocol-v1-golden.json`；现有握手协议没有定义完整业务调用，需要为任务请求、结果、取消和进度写独立扩展规格与黄金帧，评审兼容性后再实现。

大媒体不进协议帧；批量事件采用有界分块或授权项目句柄读取，任何新路径字段必须限定到用户授权包根目录。仅启动安装目录内明确的 worker，不经 shell、不从 PATH 搜索。握手以现有 2 秒为基线；长任务使用独立超时、取消与进度，不能套用握手超时。stderr 不直接进入用户日志。

macOS 继续保留 Swift 回退；Windows 没有可假设存在的 Swift 回退。worker 故障时保住原始媒体，禁用失败的自动处理并提供重试；基础播放/文件导出保持可用。项目写入服务在创建新项目之前必须就绪；录制期间的分片日志由平台持久化层独立保障，worker 崩溃不得使录制失去恢复记录。

## 4. Windows 平台实现规格

### 4.1 捕获、图形与 DPI

主链为 Windows Graphics Capture → D3D11 → 裁切/合成 → 编码或图片输出。系统能力探测失败时明确标记来源不可录制，首版不自动切换到另一种会改变捕获范围的后端。WGC 提供窗口/显示器帧；具体 Win32 互操作和选择器须在 W0 原型中验证。[官方屏幕捕获文档](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture)

应用开启 Per-Monitor DPI Awareness V2；分别维护桌面物理像素、窗口逻辑单位、素材像素和归一化坐标，唯一转换模块有往返测试。区域录制首版限定单个显示器；跨屏截图允许逐屏取样后按明确比例合成。屏幕布局变化后取消旧选区，不复用失效坐标。

控制条及选区窗尝试 `WDA_EXCLUDEFROMCAPTURE` 并检查返回值；这不是安全保护机制。最终媒体验证浮层确实被排除，失败则启用隐藏控制条与托盘控制，不能只凭 API 返回值验收。[官方窗口捕获排除说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)

首版标准导出 SDR/sRGB；HDR 输入须通过已验收的色调映射到 SDR，未通过前拒绝该模式并说明原因。不得直接把高动态范围纹理当普通 8 位图导致泛白。保护内容、UAC 安全桌面及受限来源不承诺可捕获；真实黑色内容不能仅凭全黑像素判定为权限失败。

### 4.2 音视频与恢复

WASAPI loopback 捕获输出设备混音，麦克风独立采集；统一映射到单调时钟，音频重采样处理漂移。loopback 使用共享模式，不要求用户启用硬件“立体声混音”。[官方 WASAPI 说明](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)

Media Foundation 编码器启动前完成硬件能力探测；优先硬编，软件回退需明确性能限制。GPU device lost 时先封存可读分片，再尝试重新初始化；无法续录则标记 interrupted。写盘队列和纹理池必须有界，不以无限积压掩盖编码跟不上。

录制状态为 Idle → Preparing → Recording ↔ Paused → Finalizing → Ready；故障进入 Interrupted/Failed，后处理另有 Pending/Running/Completed/Failed/Cancelled。停止和恢复操作必须幂等；连续点击停止只能产生一个最终项目。

以不超过 5 秒的可独立解码分片作为 W0 验证目标，每片从关键帧开始，索引在素材关闭并确认可读后原子提交。若平台编码链不能达到该恢复粒度，必须在 W0 改选可恢复容器/写入方案，不得延后到发布时发现。低于 5 GiB 警告、低于 1 GiB 安全停止，并加入按实时码率计算的剩余时间预警。

异常退出后扫描分片和索引，校验可解码时长，裁齐侧轨和越界事件，仅重建派生层；不得宣称普通未封口 MP4 一定可恢复。损坏分片保留供诊断，恢复成功的媒体写到新文件。

### 4.3 隐私、权限与辅助功能

仅主动录制时采集指针、点击和允许的快捷键；低级钩子只做快速入队，不做磁盘/网络操作。仅收集非文本控制键和明确允许的命令组合，排除普通文本、AltGr 字符和密码输入；无法判断的组合按不记录处理。不保存剪贴板正文、窗口标题事件流或按键原值日志。

麦克风/摄像头权限与设备占用分别识别，提供对应系统设置入口；不照搬 macOS 的 TCC 或辅助功能授权流程。无权限时允许只录屏。具备高对比度、浅深色、减少动画、Narrator 语义、完整键盘操作和 200% 文本缩放；材质可降级，不能降低文字可读性。

## 5. 项目格式与跨平台兼容

以 [开放项目格式](Lens-开放项目格式-v0.1.md) 和源码 `LensProjectSchema.portableDocuments` 为权威，不从旧文档复制固定版本号作为新实现常量。

1. `.lens` 在 Windows 是普通目录。首版通过“打开项目”选择目录/manifest，并支持从素材库定位；不假设注册扩展名就能双击目录启动应用。
2. 原始 `raw/` 不改写，读取旧项目不写回，索引可重建；保存新版本先备份相关元数据，再原子替换。未知未来 schema 拒绝编辑，显示升级提示。
3. 路径使用包内相对路径与统一分隔符；拒绝绝对路径、盘符、UNC、`..` 逃逸、备用数据流、Windows 保留名和大小写碰撞。解析后检查 junction/symlink/reparse point 不得越过授权根目录。
4. Win32 的 HWND 不能截断塞入现有 UInt32 windowID。运行时句柄不作可移植持久身份；若新增平台来源描述，须同步升级 Swift 模型、schema、文档和双端测试。
5. 先验证当前 macOS CAF/MOV 的实际编码和 Windows 解码能力。若 Windows 新写 WAV/M4A/MP4，需要按资产角色读取并先补齐 macOS 支持，不能只改文件后缀或假设旧版自动兼容。
6. 不支持的原始媒体保留，显示单轨不可播放原因；可生成兼容代理，不能覆盖原件。Windows → macOS 与 macOS → Windows 分别有真实媒体测试，不只测试 JSON。
7. 同一项目单写者加锁；云同步/网络目录首版不支持实时录制，允许停止后复制。磁盘迁移执行“复制 → 文件数/大小/摘要校验 → 切换库根 → 用户确认删除旧库”，失败保留原库。
8. 在大小写敏感/不敏感环境、中文及空格路径、长路径、只读目录和盘符变化下验证。对不支持的文件系统明确阻止开始录制；首版录制库以本地 NTFS 为支持基线。

## 8. 构建、分发与维护

### 8.1 计划中的开发入口

新增 `Scripts/windows/check-env.ps1`、`build.ps1`、`test.ps1`、`package.ps1`、`verify-release.ps1`；这些脚本当前不存在，不应作为现成命令指导用户执行。构建输出到 `Build/Windows/<arch>/`，公开制品到 `Build/Releases/Windows/`，可用参数重定向到 E 盘。

环境检查给出缺失组件和精确版本，不擅自安装系统 SDK。NuGet、Cargo、模型缓存位置在开发指南说明，可定向 E 盘。CI 发布使用 clean commit、锁定依赖、最小权限，签名密钥放受保护的密钥服务，不进入仓库或日志。

### 8.2 安装器与发布闸门

unpackaged 应用必须显式处理 Windows App SDK 运行时部署，W0 比较自包含与框架依赖并冻结方案；不假设复制一个 EXE 就能运行。[官方部署指南](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/deploy-unpackaged-apps)

发布前生成签名安装器、应用/worker/native DLL、PDB 符号档、SHA-256、依赖及许可证清单、机器可读 release.json 和发布说明。清单包含版本、架构、最低系统、commit、工具链、依赖、文件摘要、签名身份和时间戳。验证器独立检查文件与签名链，证书不匹配/摘要错误直接拒绝安装或更新。

签名不等于保证没有 SmartScreen 提示；必须在干净机器记录实际行为，不要求关闭安全防护。内部测试证书仅用于开发测试，正式用户不能被要求安装开发根证书。

### 8.3 更新、回滚与卸载

首版至少提供检查更新和经签名验证的安装器升级；下载/重启经用户操作，录制期间延后更新。完整自动后台更新可后续实现。更新包先完整下载并验签，再切换版本，保留上一可运行版本；失败不破坏当前安装。

schema 迁移与二进制更新分开：读取不迁移，保存前备份；回滚旧程序遇未来 schema 必须拒绝写入，可打开迁移前副本，不强行降级丢字段。

卸载移除程序、托盘/开机启动/快捷方式登记，默认保留项目；清除缓存和模型可单独选择，删除原始项目需要独立确认并显示具体路径。运行中的媒体任务先安全停止。

诊断日志延续白名单和限额轮转；用户主动导出脱敏摘要。完整 dump 可能含内存数据，不默认收集上传。支持流程先核验版本/设备/错误码，再复现，禁止先建议删除项目库。

### 8.4 必交付使用文档

- `docs/windows/安装与使用指南.md`：下载验签、E 盘安装、首次配置、快捷键、截图录屏编辑导出。
- `docs/windows/权限与故障排查.md`：设备拒绝、黑屏、无声、热键冲突、剪贴板占用、模型不可用。
- `docs/windows/数据备份与项目互通.md`：库/缓存/模型位置、跨盘迁移、双端支持范围、备份恢复。
- `docs/windows/发布与回滚手册.md`：构建签名、更新、撤回、回滚、卸载与保留数据。
- `docs/windows/兼容矩阵与测试记录.md`：系统、设备、commit、测试素材、结果、已知限制。

## 9. 风险、决策闸门与完成定义

| 风险 | 处理 | 阻断点 |
|---|---|---|
| Tauri 浮层焦点/托盘/部署不满足要求 | M0 验证 Tauri + Win32 集成备选方案，以 ADR 冻结，不先扩展所有 UI | M0 |
| Rust 迁移行为漂移 | Swift/Rust 同输入黄金比较，确定性规则先迁移，macOS 不强制换核心 | W1/W4 |
| 跨平台媒体不互通 | 实测 CAF/MOV 和新容器，先补双端读能力再启用新写格式 | W1/W5 |
| GPU/驱动及长时稳定性 | 有界管线、故障恢复、硬件矩阵、独立记录软件回退档位 | W2/W6 |
| 本地识别质量或模型许可证不达标 | W0 冻结候选与评测；功能未通过不得标记完整 1.0 | W0/W5 |
| 开发范围膨胀 | W2 明确内测边界，W3–W5 补齐首版项，变更必须更新规格 | 每阶段 |
| 安装签名/运行时/升级失败 | 早做干净机器安装，发布前端到端验包与回滚 | W0/W6 |

Windows 1.0 完成必须同时满足：首版功能矩阵全部通过；G-W1 至 G-W6 达标；双端项目及真实媒体兼容有证据；无未解决的数据丢失、隐私泄露、静默错误成片缺陷；普通用户可安装、升级、恢复、卸载；上述五份使用文档与发布制品一起交付。

每个阶段评审将状态从“未开始”更新为“进行中/待验收/通过/阻塞”，证据放入 `docs/windows/` 并关联 commit。未跑测试写“未验证”，不复制 macOS 的历史测试数量证明 Windows 品质。
