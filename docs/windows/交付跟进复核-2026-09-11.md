# 交付跟进复核

对应最新执行记录的“2026-09-11 P0/P1/P2 完成”批次。依据当前源码、重新执行的测试、实际发布二进制和生成的 NSIS 脚本。本次未修改产品代码或运行安装器。

## 总体判断

较上次有实质改进：内嵌音频已映射并有非静音回归；运镜关键帧和音频配置已传入渲染；worker 已由宿主命令调用；索引指纹已包含 OCR/转写/insights 等独立文件；恢复失败不再直接标记 ready。

但不能按“全部高优缺陷完成、端到端安装验收完成”接收本批。下面四项仍需修复或补充有效验证。

## 1. 安装器未包含随包依赖（阻断安装交付）

`Scripts/windows/package.ps1` 先生成 NSIS 安装器，再把 dist、worker、ffmpeg、ffprobe 复制到发布目录。`tauri.conf.json` 没有配置相应 bundle resources 或 externalBin。

直接检查本次生成的 `Desktop/src-tauri/target/release/nsis/x64/installer.nsi`：约 638 行只有主程序 File 指令，其后的 Copy resources 和 Copy external binaries 块为空。因此发布目录存在依赖不代表 setup.exe 安装这些依赖。

修复要求：依赖准备在安装器构建前完成，明确进入 Tauri/NSIS 资源清单；必需文件缺失必须使打包失败；重新验证安装后目录和实际程序运行。不要只运行 `--print-inventory`，该分支不验证界面、worker 或媒体链路。

## 2. 关闭运镜仍然产生变焦（已用发布 worker 复现）

前端把 `camera.mode` 改为 `off`，但 `post.rs::mix_audio_and_pip_ext` 只检查关键帧是否非空，没有检查 mode。

实测使用红蓝分区合成视频，通过发布包 `lens-worker.exe` 执行 render_package：

- event-driven：右侧采样像素 RGB 为 [253, 0, 0]，处于变焦后的红色视野。
- off：相同位置仍为 [253, 0, 0]，整帧 SHA-256 与开启时完全一致。
- 清空关键帧对照：右侧为 [0, 0, 254]，恢复正确的蓝色视野。
- 原始文件 SHA-256 未变。

修复要求：渲染必须遵守 mode 开关；回归直接从项目计划经 worker 导出，比较开关对应的像素、关闭后的完整视野及原件不变。不能只测试插值函数或启用时有变焦。

证据和可重复脚本：`Build/Windows/evidence/followup-review-20260911/camera-toggle-result.json`、`verify_camera_toggle.py`。

## 3. 恢复失败后缺少可用重试路径；未完成逐片解码验收

`recover_recording_package` 只允许 state=capturing，失败后写入 recoveryFailed；批量扫描也只处理 capturing。即使修好工具环境、补回缺失音轨或修复素材，现有恢复入口仍不会重试。

分片有效性实际仅检查文件大小与 `ffprobe format=duration > 0.05`，没有读取分片日志，也没有执行逐帧解码。这与最新记录中“基于日志”“真实解码性验证”的表述不一致。

修复要求：为 recoveryFailed/部分恢复建立明确重试入口；失败原因与成功状态持久化错误不能忽略；按日志和实际解码结果选择分片，保护仍在录制的项目。增加损坏视频载荷但容器时长正常、依赖恢复后重试及原始资产保留测试。

## 4. Ducking 测试尚不能证明产品输出在讲话期间正确衰减

`sidechain_ducking_attenuates_system_audio_during_speech` 对产品生成的 ducked/noduck 输出，仅比较讲话前的静音段。其讲话期间衰减断言，来自测试另行手写 FFmpeg sidechaincompress 命令生成的 sys_ducked_check.wav，而非产品输出；也未验证产品停讲后的恢复。

当前侧链处理已接入，这是实际进展。但这个测试仍可能在产品 ducking 失效时通过。代码把衰减 dB 映射为压缩比，不能仅据此宣称精确达到 -12 dB。

修复要求：从产品生成文件分离/测量系统声频段，比较开关、讲话前/中/后的增益及多个强度。断言必须作用于真实 render/export 输出，不使用旁路手写过滤器替代。
