## 必须优先补齐的任务

### P0-1：恢复成功状态必须可信

证据：`lens-project/src/lib.rs::recover_incomplete_recordings` 直接枚举所有 MP4，包括可能仍未完成的分片；忽略 `concat_segments`、`mix_audio` 返回值；时长探测失败使用 0，随后把项目改成 `ready` 并重写资产清单。

下一步：按分片日志和实际可解码性筛选；单独保存恢复报告；合成失败保留可重试状态和原资产信息；只有完整产物验证成功才标记 ready。需处理源素材保留、部分恢复、无可恢复分片及失败重试。

验收：有效前片 + 损坏尾片、全部损坏、FFmpeg 不可用、混音失败、重复恢复；检查项目状态、真实可播放结果与原始文件哈希。不能只检查函数返回或目标文件存在。

### P0-2：已嵌入音频不得在重渲染时丢失

证据：`post.rs::mix_audio_and_pip` 在没有外部 system/mic 侧轨时，未映射原视频音轨；无滤镜路径只使用 `-map 0:v`。Mac 等项目可能把系统音频放在屏幕视频内。

下一步：明确内嵌音轨与侧轨的选择、替代及混合规则。增加只有内嵌声音、内嵌声音加麦克风、画中画加内嵌声音三类回归，避免重复混入同一系统声。

验收：不仅检测 audio stream，还需解码检查其非静音内容与时长。

### P1-1：让安装包使用自身资源

证据：Tauri 配置含 `frontendDist`，但 `lib.rs::run` 实际启动 `frontend_server` 并导航至本地 HTTP 地址。该服务仍用 `find_dist()` 查磁盘目录及编译机路径；发布目录只有三个 EXE 和清单，没有 dist 或 FFmpeg/ffprobe，媒体处理仍直接查 PATH。

下一步：统一实际运行的资源读取路径，使用内嵌资源或明确随包资源；处理 FFmpeg/ffprobe 定位、许可证与完整依赖交付。打包失败必须失败，不能静默复制旧安装器或降为裸 EXE 后宣称安装器通过。

验收：在隔离副本或干净环境中，无源码路径、无开发工具 PATH 的条件下，验证启动页面、截图、编辑和真实视频导出。不要通过移动或删除用户现有源码模拟环境。

### P1-2：将运镜和音频选项真正接入渲染

证据：`interpolate_camera` 的调用目前只在核心单元测试；项目渲染没有消费完整运镜关键帧。`prepare_source` 只从计划读取 PiP 配置；混音函数没有 AudioMixConfig 参数，固定使用 `volume=0.9`、`volume=1.25` 与 `dynaudnorm`，不读取 ducking/normalize 开关或衰减值。

下一步：把计划参数接入统一渲染管线，运镜影响真实画面，音频开关和强度影响真实采样。加入讲话/静音时间段的检测或有效侧链处理，而不是固定调整两轨增益。

验收：相同素材、不同设置产生可解释的画面与音频差异；字幕/摄像头的坐标与遮挡正确；讲话期间系统声降低，停讲后恢复，关闭选项后不再处理。

### P1-3：提高新增效果测试的判别力

证据：`camera_pip_and_ducked_audio_are_synthesized_into_render` 仅断言文件存在、存在视频轨与音频轨、部分 raw 文件不变。即使没有画中画或没有 ducking，也可能通过。

下一步：检查摄像头区域像素、位置、大小、开关前后差异；使用不同频率的系统音与分段旁白检查真实衰减和恢复。对运镜添加指定时间的视野/缩放验证。

### P2-1：worker 与项目索引完成端到端接入

证据：worker 有任务循环，但宿主和项目渲染没有启动/调用该 worker 的链路；`spawn_blocking` 是同进程线程，不是独立进程隔离。索引缓存只取项目目录、manifest 和人工字幕文件的秒级 mtime 最大值，不跟踪 OCR、转写和 insights 的内容变化，也可能漏掉同秒修改。

下一步：worker 加客户端、真实任务路由、超时/取消/退出/重启状态；索引使用实际依赖文件的独立指纹，不用单个最大时间值代表所有依赖。

验收：终止 worker 后主程序存活、任务状态可重试；修改 OCR/转写/摘要后搜索立即更新；同秒连续编辑不返回旧内容。

### P2-2：跨端及视觉验收仍须独立执行

现有类型化黄金样本测试验证了部分字段往返与忽略未知字段，不是未知字段无损保存，更不是真实媒体双向往返。全局毛玻璃 CSS 也不能证明与 Mac 界面逐项一致。

下一步：补 Mac → Windows → Mac 及反向完整项目测试；明确未知字段写回策略；用同一操作状态比较 Mac 与 Windows 关键窗口、编辑效果、字幕、快捷键与辅助功能。

## 建议推进顺序

先完成 P0 恢复与声音保留，再修 P1 安装资源和真实效果接线，随后完成 P2 worker/索引/跨端验收。每批包含可复现缺陷、代码修复、有效回归、Release 构建和明确的待验收项。现有各阶段成果继续保留，不重写已验证的基础链路。
