# 屏迹 macOS 发布撤回与回滚手册

状态：Public Alpha/Beta 前演练候选。本文处理已经生成或公开的 macOS 版本；它不授权删除用户项目、修改系统隐私权限或处置签名凭据。

## 1. 不可破坏的边界

- App 二进制和用户数据分开处理。撤回、重装或回滚只替换 `ScreenTrace.app`，不得删除或改写 `~/Pictures/ScreenTrace/` 中的 `.screentrace` 项目。
- `raw/` 原始媒体、人工字幕/整理校正和 `edits/` 非破坏编辑计划都属于用户数据；预览和索引可重建不等于可以顺带清理项目包。
- 只使用具有不可变 URL、Git commit、`release.json`、SHA-256、dSYM 和公证记录的制品。不得重新上传不同内容并复用旧版本号、构建号或下载地址。
- 自动更新不得静默降级项目 schema。旧 App 遇到更新版本项目时应拒绝编辑；先保留原项目，再用兼容版本打开。
- Developer ID、公证 profile 和未来的更新签名私钥只留在受控钥匙串或离线签名环境，不写入仓库、发布附件、工单或聊天记录。

## 2. 每次公开前固定的发布档案

发布负责人为当前候选和上一稳定版各保留一套不可变档案：

| 证据 | 要求 |
| --- | --- |
| 源码 | 完整 Git commit，工作区为 `clean`，公开 tag 指向该 commit |
| 安装制品 | DMG、App zip，文件名包含唯一版本号和构建号 |
| 调试制品 | 与 App Mach-O UUID 一致的 dSYM zip |
| 来源清单 | `release.json` 中记录版本、最低系统、UUID、签名 Team ID、公证 request ID、尺寸和摘要 |
| 完整性 | `SHA256SUMS.txt` 覆盖 DMG、App zip、dSYM、`release.json` 和发布说明；归档清单再覆盖以上文件、原校验和与归档身份元数据 |
| 发布说明 | 权限需求、数据目录、项目格式兼容性、已知问题、支持和安全报告入口 |

当前候选和上一稳定版都必须先通过：

```bash
bash Scripts/verify-macos-release.sh Build/Releases/ScreenTrace-0.1.0-1-release.json
```

公开模式未通过时，不得把“能在开发机运行”视为可回滚制品。

当前候选可先创建不可覆盖的本地档案并独立复验：

```bash
bash Scripts/archive-macos-release.sh --development \
  Build/Releases/ScreenTrace-0.1.0-1-release.json \
  Build/ReleaseArchives

bash Scripts/verify-macos-release-archive.sh --development \
  Build/ReleaseArchives/ScreenTrace-0.1.0-1-<commit-prefix>
```

归档目录名包含 Git commit 前 12 位；同一候选不得覆盖已有目录。档案同时保留 DMG、App zip、dSYM、发布清单、发布说明、原始校验和和独立归档元数据。公开发布时移除 `--development`，两层校验都必须通过。

## 3. 触发条件与决策

### 暂停推广

用于不造成数据损坏、但明显影响体验或兼容性的缺陷。保留现有下载，停止扩大灰度，修复后以更高构建号发布。

### 撤回下载

用于无法安装/启动、大面积崩溃、错误权限行为、错误签名/公证、严重隐私问题或制品摘要不一致。立即从下载页和更新源移除该候选，但保留内部只读证据，不覆盖原文件。

### 发布回滚构建

用于已有用户安装问题版本且需要自动恢复。以“上一稳定代码 + 必要兼容修复”生成新的、更高版本或构建号；重新签名、公证、生成清单并完整验收。不要让更新客户端接受版本号倒退，也不要用旧文件冒充新构建。

若存在原始素材丢失、凭据泄露或恶意制品风险，直接按安全事件处理，不等待普通缺陷复现。

## 4. 撤回步骤

1. 冻结发布：停止更新源生成、下载页推广和新附件上传，记录决定时间、负责人、受影响版本/构建号和 Git commit。
2. 保存证据：记录公开 URL、下载到的实际 SHA-256、`release.json`、公证 request ID、错误代码和脱敏复现步骤；不收集用户媒体或项目正文。
3. 独立复核：从公网重新下载一次，比较摘要并运行发布验收器；区分“制品被替换”“签名/公证失效”和“应用逻辑缺陷”。
4. 撤下入口：下载页和更新源不再向新用户提供问题版本。保留内部隔离副本和符号文件，避免后续崩溃无法定位。
5. 指定恢复路径：明确上一稳定版，或指定新的回滚构建；未完成全套验收前不对外给出临时包。
6. 发布状态说明：写清影响、受影响版本、是否涉及用户数据、当前缓解措施和下一次更新时间；不要猜测尚未确认的根因。

## 5. 回滚构建与验证

1. 从上一稳定 tag 建立修复分支，只合入兼容性和安全所需改动；保留问题版本后的项目 schema 读取能力。
2. 使用新的单调递增版本/构建号执行 Release 构建、Developer ID 签名、App/DMG 公证和 Staple。
3. 运行全量测试、warnings-as-errors Release 构建、公开源码审计、打包和公开模式发布验收器。
4. 在没有开发证书的 Mac 和干净用户账户安装；验证首次启动、Gatekeeper、权限说明、截图、录屏、导出和旧项目只读/编辑兼容性。
5. 从问题版本覆盖安装回滚构建，确认快捷键、媒体偏好、屏迹库索引和用户项目仍在；不得以删除偏好或重置 TCC 作为通过条件。
6. 断网启动并打开已有项目，确认 Staple 有效且核心本地功能不依赖发布服务器。
7. 公开后从公网重新下载，复核 SHA-256，并把最终 URL、摘要、commit、UUID 和公证记录写回发布档案。

## 6. 用户手动恢复

- 先退出屏迹，并用 Finder 将整个 `~/Pictures/ScreenTrace/` 复制到独立备份位置；不要只备份 `previews/`。
- 将经过公开验收的恢复版本 App 安装到 `/Applications`。只替换 App，不移动、重命名或删除项目目录。
- 若旧版本提示项目 schema 过新，保留项目原样，重新安装能够读取该 schema 的稳定版本；禁止手工降低 JSON 版本号。
- 恢复后先复制一个项目做打开/导出冒烟，再处理原项目。任何自动修复都必须保留原始媒体和可恢复副本。

## 7. 自动更新接入前置门槛

- 先确定更新框架、更新源所有权、发布通道和最低支持版本，再更新 `PRIVACY.md` 中当前“不包含自动更新网络客户端”的声明。
- 更新签名密钥与 Developer ID 分离管理；记录轮换、吊销、离线备份和双人恢复流程。
- 更新清单必须使用 HTTPS、不可变制品 URL、版本/构建号、文件长度和加密签名；客户端对签名、长度或版本异常一律拒绝并保留当前 App。
- 至少覆盖稳定版→候选、候选→回滚构建、断网、超时、404、损坏包、错误签名、重复构建号和更新中强退。
- 自动更新只能替换 App；不得把项目迁移、索引清理、权限重置或遥测启用藏在更新安装阶段。

## 8. 安全凭据事件

发现 Developer ID、钥匙串公证 profile、更新签名私钥或发布账号可能泄露时：立即暂停发布和更新源，由账号持有人在 Apple/托管平台完成吊销或轮换；本仓库只记录非敏感 request ID、Team ID、时间和受影响制品摘要。新凭据验证完成前不得恢复自动发布。

## 9. 演练完成标准

- 能在不触碰测试用户项目的前提下撤下一个候选并恢复上一稳定能力。
- 问题版本、恢复版本和上一稳定版的 commit、摘要、UUID、签名、公证与 dSYM 都可追溯。
- 覆盖安装、全新安装、断网启动、过新项目拒绝、损坏更新包和回滚构建更新均留存结果。
- 发布状态说明、支持入口和安全公告模板可在一次演练中完成，不依赖个人口头记忆。
