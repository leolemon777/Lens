# 屏迹 macOS 安装、权限、升级与卸载

当前状态：仓库只生成开发用 ad-hoc 签名 App，尚无经 Developer ID 签名和 Apple 公证的公开安装包。本文档同时记录开发阶段的实际流程和 Public Beta 发布前必须替换的部分。

## 从源码构建

需要 macOS 15 或更高版本、Xcode 和 Swift 6 工具链：

```bash
swift test
bash Scripts/build-app.sh release
open Build/ScreenTrace.app
```

App 生成在 `Build/ScreenTrace.app`。开发包使用 ad-hoc 签名，仅用于本地验证。

## 首次启动与权限

1. 启动屏迹，在权限中心查看当前状态。
2. 首次截图或录屏时，在“系统设置 → 隐私与安全性 → 屏幕与系统音频录制”中允许 ScreenTrace。
3. 只有开启讲解声或摄像头时才授予麦克风/摄像头权限。
4. 只有生成转写时才授予语音识别权限。Apple 设备端识别不可用时，屏迹不会自动回退云端。
5. 权限改变后退出并重新启动 App，再回到权限中心复核。

默认快捷键：

- `Fn + Control`：快速区域截图；
- `Fn + Space`：打开操作中心；
- `Control + Option + 1` / `Control + Option + 2`：无 Fn 备用组合。

物理 `Fn` 键必须在真实键盘上验证，自动化合成按键不经过相同的 Carbon 全局热键通道。

## ad-hoc 签名与 TCC 限制

开发脚本每次重新打包都可能生成新的代码身份。macOS TCC 权限可能仍显示名为 ScreenTrace 的开启记录，但新构建实际不被该记录覆盖。如果权限中心与实际捕获结果不一致：

1. 退出 ScreenTrace；
2. 在对应的“隐私与安全性”页面关闭并重新开启 ScreenTrace；
3. 重新启动当前的 `Build/ScreenTrace.app`；
4. 仍不一致时，不要删除项目数据，先复制脱敏诊断摘要并记录当前 App 路径与签名类型。

Public Beta 必须改用稳定 Developer ID 身份和公证包，不能要求普通用户重复处理这个开发阶段限制。

## 数据位置与备份

- 开放项目包：`~/Pictures/ScreenTrace/`；
- 诊断日志与会话健康标记：`~/Library/Application Support/ScreenTrace/diagnostics/`；
- 快捷键、媒体和转写偏好：`~/Library/Preferences/app.screentrace.mac.plist`。

升级、迁移或测试恢复前，首先备份 `~/Pictures/ScreenTrace/`。项目包中的 `raw/` 是恢复与重新生成成片的依据，不应只备份预览文件。

## 升级开发构建

1. 退出正在运行的 ScreenTrace，确认没有正在捕获或后台转写的项目。
2. 备份 `~/Pictures/ScreenTrace/`。
3. 构建新 App 并替换旧的开发副本；不要覆盖用户项目目录。
4. 启动后验证旧项目、快捷键、媒体偏好和索引重建。
5. 如果捕获权限失效，按上述 TCC 限制处理。

## 卸载

删除 `ScreenTrace.app` 不应自动删除用户的 `.screentrace` 项目。如果只想卸载应用但保留素材，保留 `~/Pictures/ScreenTrace/`。

如果用户明确要求完全清除，退出 App 并备份需要保留的项目后，再单独删除：

- `~/Pictures/ScreenTrace/`；
- `~/Library/Application Support/ScreenTrace/`；
- `~/Library/Preferences/app.screentrace.mac.plist`。

macOS TCC 权限和系统崩溃报告不在上述目录中；分别在“系统设置 → 隐私与安全性”和 `~/Library/Logs/DiagnosticReports/` 中管理。
