## 1. 产品定义

> 屏迹是一款本地优先、开源、AI 原生的截图与录屏工作台：一按即捕捉，停下即成品，之后永远找得到。

屏迹 1.0 解决四件事：

1. **快捕获**：快捷键出现捕获层，截图和录屏都不需要先打开主窗口。
2. **立即可用**：截图立即进入剪贴板；录屏停止后原始文件立即可播放。
3. **自动成片**：录屏自动完成光标、缩放、背景、音频和字幕的第一版处理。
4. **智能整理**：截图和录屏统一进入屏迹库，由 OCR、转写与 AI 自动命名、搜索和整理。

## 2. 1.0 的产品原则

### 2.1 捕获不能被编辑器拖慢

- 捕获进程常驻但保持轻量。
- 完整编辑器按需加载。
- AI 和自动剪辑都在捕获完成后异步执行。
- 即使自动处理失败，原始截图和录屏也必须可用。

### 2.2 默认完成，用户负责修正

- 默认给出可直接分享的结果。
- 编辑器用于修正自动结果，而不是每次捕获的必经步骤。
- 所有自动处理均非破坏性、可关闭、可撤销。

### 2.3 本地优先，不等于拒绝分享

- 无账号即可完成捕获、编辑、整理和导出。
- 默认不上传媒体。
- 分享采用可选的本地文件、iCloud、用户自有 S3/R2 或未来的官方服务。

### 2.4 开放项目格式

- 原始媒体、事件、转写、编辑计划分离。
- 项目包可以被第三方工具、插件和 AI Agent 读取。
- 停止维护后，用户仍然能取回原始素材和编辑信息。

### 2.5 macOS 体验优先，边界从第一天支持 Windows

- macOS 捕获和浮层使用原生技术保证速度与系统感。
- 项目模型、媒体处理、自动编辑规则尽量跨平台。
- Windows 后续只替换平台捕获适配器，不重写整个产品。

### 2.6 吸收竞品优势，但不做功能拼盘

- PathShot、HuaStudio、Kite、ShotGlass，以及调研中的 Screen Studio、FocuSee、CleanShot、PixPin、Tella、Loom、Cap 等产品，其核心优势必须进入《全景功能与竞品能力吸收矩阵》；
- 每项能力都必须明确：参考价值、屏迹形态、所在里程碑、验收方法和隐私/性能代价；
- “做进去”指独立实现同类价值与效果，不复制对方的界面、素材、品牌表达或受许可证限制的代码；
- 全部能力可以存在，但不能全部同时出现在默认界面；高频动作一键完成，高级能力渐进展开；
- 1.0 优先完成可靠的完整闭环，复杂演示能力进入已排期的 1.x 路线，不成为永远搁置的“以后再说”。

### 2.7 原生“迹光玻璃”是产品级约束

- 屏迹在 macOS 上应像 Apple 第一方工具自然生长出来，而不是普通窗口叠加一层模糊；
- 捕获层、`Fn + Space` 操作中心、录制控制条、Quick Access、编辑器外壳和设置优先使用 Swift、AppKit 与 SwiftUI 原生实现；
- 在 macOS 26 使用系统原生玻璃效果、交互态和形变能力，旧系统使用原生视觉材质降级；
- 玻璃只承担导航、控制和状态，截图或视频内容本身必须保持清晰、稳定、色彩可信；
- 必须支持浅色、深色、降低透明度、增强对比度和减少动态效果等辅助功能设置；
- 视觉默认克制、安静、内容自适应，不使用廉价霓虹、过度描边或无意义的持续动画。

## 3. 产品表面

屏迹 1.0 由六个主要表面构成：

1. **捕获层**：`Fn + Control` 直接进入快速截图，`Fn + Space` 唤起完整操作中心。
2. **录制控制条**：来源、音频电平、暂停、停止、时间和磁盘状态。
3. **Quick Access**：捕获完成后的悬浮缩略图与最近素材架。
4. **统一编辑器**：截图画布与视频时间线，共享背景、标注和导出体系。
5. **屏迹库**：历史、搜索、OCR、转写、标签、项目和 AI。
6. **设置与权限中心**：快捷键、保存、录制、隐私、AI、分享和系统权限。

### 3.1 双入口启动模型

屏迹采用“直接动作 + 操作中心”两个入口，避免简单截图和复杂操作互相拖累。

#### `Fn + Control`：快速截屏

- 按下后立即进入智能区域截图；
- 悬停窗口时自动识别窗口边界；
- 拖动时进入自由区域选择；
- 完成后立即复制到剪贴板，并按设置自动保存；
- 不弹出模式选择页，不加载完整编辑器；
- Quick Access 只在捕获完成后轻量出现。

这条路径服务于最高频任务，目标是形成肌肉记忆：

```text
Fn + Control → 选区 → 完成 → 已经可以粘贴
```

#### `Fn + Space`：屏迹操作中心

`Fn + Space` 唤起一个由常驻捕获进程提供的轻量浮层，而不是直接启动完整主窗口。

浮层第一版包含：

- 区域、窗口、全屏和多窗口截图；
- 区域、窗口和全屏录制；
- 长截图、OCR、贴图；
- 最近几条截图和录屏；
- 打开编辑器、屏迹库和设置；
- 对最近素材执行复制、分享、AI 整理等上下文操作。

行为规则：

- 再按一次 `Fn + Space` 或按 `Esc` 关闭；
- 支持键盘继续选择动作，避免必须使用鼠标；
- 打开时优先显示最近操作和当前上下文；
- 录制进行中时，`Fn + Space` 优先显示录制状态、暂停和停止；
- 编辑器和屏迹库只在用户明确选择后延迟加载。

```text
Fn + Space
  ├── 新建截图
  ├── 新建录屏
  ├── OCR / 长截图 / 贴图
  ├── 最近屏迹与上下文操作
  └── 编辑器 / 屏迹库 / 设置
```

#### 快捷键兼容要求

- `Fn` 在 macOS 中属于特殊硬件修饰键，需要验证内置键盘、Magic Keyboard 和第三方键盘；
- 默认提供 `Fn` 方案，但所有快捷键必须允许自定义；
- 提供不依赖 `Fn` 的备用快捷键；
- 处理按键长按、重复触发、输入法切换和系统 Globe/Fn 功能冲突；
- 权限中心需要清楚解释全局按键监听所需权限及用途。

## 4. 为什么先做 UI，但不是先画视觉稿

UI 阶段首先解决的是流程、状态和优先级，而不是颜色、玻璃效果和图标。

正确顺序：

1. 用户任务与关键路径；
2. 信息架构；
3. 捕获与录制状态机；
4. 低保真线框；
5. 可点击交互原型；
6. 技术可行性校验；
7. 视觉语言和设计 Token；
8. 高保真组件；
9. 实际产品实现。

UI 原型需要覆盖以下完整流程：

- 区域截图 → 标注 → 剪贴板 → Quick Access；
- 窗口/多窗口截图 → 背景美化 → 拖到其他 App；
- 长截图 → 拼接预览 → 裁切 → 保存；
- 区域录屏 → 检查声音 → 开始 → 暂停 → 停止；
- 停止录屏 → 原始文件可用 → 自动处理 → 快速预览；
- 打开编辑器 → 修正缩放/剪切/字幕 → 导出；
- 打开屏迹库 → 搜索 → AI 整理 → 生成教程或短版本；
- 权限缺失、磁盘不足、录制中断、恢复失败等异常流程。

## 5. UI 阶段同步进行的技术验证

UI 不能脱离真实技术约束，因此交互原型阶段同步完成六个小型技术验证：

1. `Fn + Control`、`Fn + Space` 全局快捷键和原生透明浮层的响应速度；
2. ScreenCaptureKit 截图的窗口、多屏、Retina 和坐标映射；
3. 30/60 FPS 录屏以及系统声音、麦克风分轨；
4. 鼠标位置、点击、形状、键盘和活动窗口事件采集；
5. 视频分片写盘、中断恢复和快速 finalization；
6. Swift 捕获进程、Rust 核心和共享编辑器之间的数据边界。

这些验证不追求完整产品，只负责回答“能不能稳定做到”和“UI 应该如何表现”。

## 6. 技术结构基线

原生 UI 原型与媒体测试已经确认第一版采用以下结构：

```text
ScreenTrace for macOS
Swift + AppKit + SwiftUI
        │
        ├── Capture Agent / Global Hotkeys
        ├── Overlay / Action Center / Quick Access
        ├── ScreenCaptureKit / AVFoundation / Core Image
        └── Native Editor Shell / Settings / Library
                    │
                    ▼
Cross-platform Core
Open project model + deterministic effect plan
        │
        ├── Media metadata
        ├── Event processing
        ├── Auto-camera / cursor / interaction rules
        ├── Recovery / validation
        └── Rust migration boundary for Windows
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
Native Media Renderer     AI Worker
AVFoundation/Core Image   Local models / BYOK
          │                   │
          └─────────┬─────────┘
                    ▼
              Trace Library
          SQLite + project packages
```

macOS 关键表面和编辑器外壳原生优先，不再以 Tauri/React 作为默认方案。跨平台复用的是项目格式、效果计划、事件算法与未来的 Rust 核心，不以牺牲 macOS 原生体验换取同一套 UI。

├── events/
│   ├── pointer.jsonl

### M4：录屏完整闭环 Alpha

交付：

完成标准：一小时录制音画同步；强制中断后可以恢复；停止后不等待自动编辑即可播放原始视频。

交付：

## 10. 关键体验指标

以下是目标值，需要在技术验证后调整：

- 快捷键到捕获层出现：100–150ms；
- 截图到剪贴板可用：约 300ms；
- 停止录屏到原始视频可播放：1 秒内；
- 常驻捕获进程保持低内存、低 CPU、空闲零明显耗电；
- 典型一分钟录屏的自动草稿在后台快速完成；
- 连续 100 次截图无失败；
- 一小时录屏无明显音画漂移；
- 崩溃恢复不丢失已写入的媒体分片；
- 80% 的日常捕获无需打开完整编辑器。

## 11. 主要风险

| 风险 | 应对方式 |
|---|---|
| 功能过多导致启动和 UI 变重 | 捕获 Agent 与编辑器分离；渐进式披露 |
| ScreenCaptureKit 权限和系统版本差异 | 独立权限中心、系统版本测试矩阵、原生 Content Picker 评估 |
| 音画同步和长时间录制丢失 | 分片写盘、独立时钟、恢复与 remux 流程 |
| 自动缩放判断错误 | 事件驱动、置信度、自动结果可编辑 |
| AI 处理泄露内容 | 默认本地、BYOK、逐项授权、AI 可完全关闭 |
| 过早跨平台导致 macOS 体验妥协 | 只共享核心与编辑器；平台捕获层保持原生 |
| 引入不兼容开源代码 | 建立依赖和许可证清单；GPL/AGPL/BSL 项目只在许可允许范围内参考 |

## 12. 立即执行顺序

当前执行采用“可运行纵向切片 + 测试闭环”：

1. PathShot 审计与能力矩阵（已完成）；
2. `Fn + Space` 原生迹光玻璃操作中心（已完成首个可运行版本）；
3. 区域、独立窗口和当前显示器截图、项目包、剪贴板及 Quick Access（已编码，待系统权限后的完整 E2E）；
4. 原生录制控制条、ScreenCaptureKit 原始录屏、事件分轨和中断恢复（首个纵向切片已编码）；
5. 自然模式自动运镜、鼠标平滑、点击反馈、背景、圆角、阴影与 MP4 渲染（首个纵向切片已通过媒体集成测试）；
6. 音频电平/自动混音、摄像头合成、九类高级截图标注、滚动长截图、统一视频编辑器、持久素材索引与本机短录屏转写已完成首个可测纵向片；当前继续补齐长录屏分段转写、字幕、标签与 AI 整理；
7. 每项能力执行“编码 → 自动测试 → 本机 UI 测试 → 修复 → 回归测试”；
8. 达到对应里程碑的可靠性门槛后再进入下一发布级别。

第一批 UI 重点只放在三块：

- 捕获层；
- 录制控制条；
- Quick Access。

这三块决定屏迹能否真正做到“快”和“无打扰”，也会决定后续编辑器与素材库的数据入口。
