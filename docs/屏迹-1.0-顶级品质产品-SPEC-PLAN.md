## 1. 产品定义

### 1.1 一句话定位

> 屏迹是 macOS 本地优先的截图与演示录屏工作台：截得快，录完好看，原始素材和编辑计划永远属于用户。

### 1.2 核心用户

按 1.0 付费优先级排序：

1. 独立开发者、设计师、产品经理：每天截图，每周制作产品演示；
2. 技术写作者、支持工程师、教育工作者：需要教程、问题复现和可搜索素材；
3. 隐私敏感的专业用户：不愿把录屏和转写默认上传云端；
4. 需要开放工程包的工具开发者：希望脚本、Agent 或其他编辑器读取素材与计划。

### 1.3 核心待办任务

用户雇用屏迹完成的不是“打开一个截图软件”，而是：

- 把屏幕上的内容在几秒内放进聊天、设计稿或文档；
- 把一段产品操作快速变成可分享、可修改的演示视频；
- 在意外中断后保住原始素材；
- 过一段时间仍能找到、重新编辑并导出过去的捕获；
- 在不登录、不上传原始媒体的情况下完成核心流程。

### 1.4 产品承诺

1. 每次启动都快；
2. 每次捕获都明确成功或明确失败；
3. 停止录屏后原始素材立即可用；
4. 自动结果是可修改的草稿，而不是不可逆结果；
5. 任何后期失败都不能破坏原始素材；
6. 默认不要求账号、不上传、不记录普通键盘文本；
7. 预览与导出保持一致。

## 2. 产品策略

### 2.1 北极星指标

北极星指标是“从捕获意图到可交付结果的时间”，分成两类：

- Screenshot Time to Useful：按下快捷键到图片可复制、拖出或贴图；
- Recording Time to Draft：停止录屏到可播放原始素材和可编辑自动草稿。

功能数量、时间线工具数量和 AI 标签数量都不是北极星。

### 2.2 两个黄金闭环

#### 黄金闭环 A：快速截图

快捷键 → 选择区域/窗口/屏幕 → 原图落盘并进入剪贴板 → Quick Access → 复制/拖出/标注/贴图 → 自动入库

成功结果：

- 80% 日常截图不打开完整编辑器；
- 用户不需要寻找导出目录；
- 关闭 Quick Access 后仍能从历史恢复。

#### 黄金闭环 B：演示录屏

选择来源 → 确认音频与摄像头 → 稳定录制 → 停止后立即播放原始素材 → 自动生成非破坏草稿 → 少量调整 → 导出

成功结果：

- 停止后不等待 AI 或渲染即可打开原始视频；
- 默认草稿已经包含可用的镜头、光标、画布、音频和字幕；
- 所有自动效果都能单独关闭；
- 导出失败仍可重新打开项目。

### 2.3 真正的差异化

屏迹不能再把“自动缩放”或“有项目文件”单独当作护城河。Recordly、OpenScreen、Cap 等项目已经覆盖其中一部分。

可防守组合是：

1. 截图与录屏共享一个捕获入口、历史库、样式和项目模型；
2. raw、events、analysis、edits、previews 清晰分层；
3. 原生 macOS 捕获、分片恢复和长时间可靠性；
4. 自动成片完全非破坏、可解释、可撤销；
5. 本地优先和主动捕获，而不是 24/7 监控；
6. 开放格式可被脚本、插件和未来平台层读取。

## 3. 1.0 明确不做

以下能力不阻塞首个 macOS 公开版本：

- Windows 正式版或跨平台 UI；
- Loom 式团队空间、评论、观看分析和 SSO；
- OBS 式直播、场景市场和编码插件生态；
- Camtasia/ScreenFlow 式重型多轨 NLE；
- 24 小时被动屏幕记忆；
- 默认依赖云端生成式模型；
- 复杂 3D 摄影棚、AI 配音市场和音乐素材商城；
- 为追求功能数量而增加的低频检查器与设置。

这些方向只能在 macOS 留存、质量和商业模式得到验证后进入 1.x 或 2.0。

## 4. 体验场景

### SC-01：日常截图发送

用户按截图快捷键，框选内容，图片立即进入剪贴板，Quick Access 显示缩略图。用户可直接把文件拖进聊天或文档，并收到简短成功反馈。

### SC-02：截图标注与隐私遮挡

用户截完后立即画箭头、文字、编号、模糊或安全遮挡，Command+C 复制最终结果。对象保持可编辑，导出前明确区分视觉模糊和不可恢复的安全遮挡。

### SC-03：长页面留档

用户在 Safari、Chrome/Edge 或普通原生滚动视图中选择长截图，捕获过程可取消，最终输出无重复页头、无明显断层，并保留源帧和拼接计划以便诊断。

### SC-04：单窗口产品演示

用户从实时窗口缩略图中选择浏览器或 App，摄像头保持关闭，确认系统音频和麦克风后开始录制。浮标始终可见但不进入成片。

### SC-05：自动成片

用户停止一分钟产品演示后立即播放原始视频。后台生成自然成片草稿，包含克制运镜、平滑光标、画布、人像避让、音频与字幕；用户只需少量修改即可导出。

### SC-06：异常恢复

录制过程中遇到强退、设备拔出、系统流中断或空间不足。应用重新打开后识别未完成会话，保留可恢复分片并给出清晰选择，不覆盖已有项目。

### SC-07：重新查找与再编辑

用户通过标题、OCR、转写或标签找到历史 Trace，打开非破坏编辑计划，修改后再次导出，原始媒体保持不变。

### 5.6 自动运镜

自动运镜提供三个用户可理解的模式：

| 模式 | 行为 | 适用场景 |
|---|---|---|
| 自然成片 | 缩放少、默认 1.60×、停留长、自然回退 | 完整演示、课程、工作汇报 |
| 聚焦演示 | 点击、输入区域和窗口切换更主动地驱动镜头 | 产品教程、功能说明、短视频 |
| 手动控制 | 不自动写入镜头，只提供可接受或忽略的建议 | 对镜头有明确意图的用户 |

“成片模式”决定整体风格，“生成强度”决定本次自动镜头的响应程度，两者不能混为同一个开关。编辑器提供克制、适中、积极三档生成强度：

| 生成强度 | 行为 | 约束 |
|---|---|---|
| 克制 | 只响应高置信点击与明确意图，镜头少、停留长、移动慢 | 默认用于长演示，不因连续小操作频繁推拉 |
| 适中 | 在镜头数量、倍率、停留和回退间保持平衡 | 作为通用默认值 |
| 积极 | 更主动响应点击和焦点变化，允许更高倍率和更短冷却 | 仍必须聚类连续点击，并遵守安全区和最大移动速度 |

起始调参范围只作为盲测基线，不作为固定 API：

- 新录屏的自动运镜默认倍率统一为 `1.60×`，模式差异由触发频率、聚类、停留和回退节奏表达，避免用户在模式间得到不可预期的构图尺度；
- 默认自然成片的推近过程约 `0.68` 秒，克制档约 `0.82` 秒；点击先在真实位置显示，随后才把目标区域平滑带到视觉中心；
- 连续点击聚类为一个意图，避免每次点击重新起镜；
- 滚动、鼠标路过和无结果点击不得高频触发；
- 输入区域可以驱动构图，但不能记录普通输入文本；
- 靠近边缘时先保证内容安全区，再决定平移或缩放；
- 任意自动镜头都能拖动、调整、删除、锁定或全部关闭。

| ID | 要求 | 验收 |
|---|---|---|
| AUTO-01 | 事件融合使用点击、指针速度、窗口变化、停留和可选活跃控件 | 单一噪声事件不触发镜头 |
| AUTO-02 | 具备死区、最短停留、冷却时间和最大移动速度 | 长流程无抽动、无追鼠标、无连续呼吸 |
| AUTO-03 | 点击聚类和重复操作形成稳定段落 | 一组相关操作不产生多次无意义缩放 |
| AUTO-04 | 镜头计划绑定源时间并保持非破坏 | 剪切、变速、重排后仍可正确映射 |

| CUR-05 | 摄像头、字幕和光标聚焦区域使用同一避让规则 | 预览和导出位置一致 |
| CUR-06 | 快捷键胶囊只显示明确允许的组合键 | 不记录普通文本、密码或完整键盘内容 |
| CUR-07 | 编辑器集中提供重绘光标、点击波纹、光标大小和平滑控制 | 修改后可即时预览，保存、重开和导出参数不丢失 |
| CUR-08 | 平滑使用用户可理解的时间窗口显示，`0 ms` 表示原始路径 | 快速移动仍自然；点击帧和拖动端点不得被平滑带偏 |
| CUR-09 | 点击波纹支持开关、大小、颜色和持续时间 | 默认样式在浅色、深色和复杂背景上均清晰，且不会遮挡目标控件 |
| CUR-10 | 光标重绘、平滑和波纹全部基于原始事件非破坏生成 | 关闭任一效果可恢复对应原始表现，不改写原始录屏或事件轨 |
| CUR-11 | 新录屏记录隐私安全的标准系统光标形态轨 | 链接、文本、拖拽和缩放等标准形态可在成片中还原；未知或缺失形态回退箭头 |
| CUR-12 | 光标本体、移动特效和点击反馈互相独立 | 任一层可单独选择预设、调整强度或关闭，保存、重开和导出一致 |
| CUR-13 | 高级光标效果不回退播放流畅度 | 效果在后台烘焙进预览；播放仍使用已生成媒体，不在 SwiftUI 高频重绘 |
| CUR-14 | 原始媒体实时预览与成片都必须显示光标、点击和拖动状态 | 调整任一参数后不出现“镜头跟随一个看不见的鼠标”；按下、拖动、释放时序可辨 |

### 5.7.1 自动运镜与光标控制改造包

按以下依赖顺序交付，避免只有界面控件而没有真实成片效果：

1. **项目模型与兼容**：增加点击自动推近开关、绝对倍率、生成强度、运动模糊强度、平滑时间窗口和波纹样式；旧项目迁移后视觉保持不变。
2. **镜头规划器**：让三档强度真正驱动触发阈值、点击聚类、镜头停留、冷却、倍率和回退；为自动、手动、锁定关键帧保留明确来源。
3. **重新生成事务**：从原始点击/指针事件重算自动镜头，原子替换自动关键帧，保留人工内容，并纳入统一撤销/恢复。
4. **渲染器**：实现速度驱动的基础运动模糊、可配置高清光标和点击波纹；关闭效果时不残留模糊或额外合成。
5. **编辑器面板**：按照“自动运镜”和“光标与点击”分组，提供即时预览、明确数值、重生成进度和成功/失败反馈。
6. **验证**：增加模型迁移、规划器、撤销、逐帧渲染、UI 快照、真实性能和竞品匿名盲测；所有测试同时覆盖预览与最终导出。

## 6. 视觉与交互规格

### 6.1 迹光玻璃原则

极致玻璃不是把透明度拉满，而是材质、层级、光线和响应的一致。

1. 内容比玻璃重要；截图和视频色彩不能被控制层污染；
2. 只定义三种主要玻璃层级：控制面、浮层、检查器；
3. 高风险和高频动作必须有清晰文字或辅助功能名称；
4. 浅色、深色、复杂壁纸、增强对比度和降低透明度都必须可读；
5. 玻璃降级不能阻断任何捕获功能；
6. 圆角、描边、模糊和阴影必须来自设计令牌，禁止局部随意值。

### 6.2 动效

- 按下和悬停即时响应；
- 普通状态转换以约 160–240ms 为起始范围；
- 捕获开始、停止、复制和保存不能等待动画；
- 动画可被反向操作或新状态中断；
- 开启减少动态效果后改为短淡入淡出；
- 不允许由于动画排队造成重复停止、重复导出或布局跳动。

### 6.3 成功反馈

- 复制：短 Toast“已复制”；
- 保存：说明保存位置，可提供 Finder 动作；
- 拖出：拖动开始时显示文件语义，放置成功由目标 App 反馈；
- 导出：显示完成制品、打开、复制和 Finder；
- 失败：说明影响范围、原始素材是否安全及下一步动作；
- 不使用仅靠颜色或图标表达关键结果。

### 6.4 视觉回归

必须覆盖：

- 1x/2x 缩放；
- 浅色、深色；
- 高对比度；
- 降低透明度；
- 减少动态效果；
- 常规、窄窗口、最小窗口；
- 多屏边缘与全屏辅助窗口；
- 无数据、处理中、失败和完成状态。

## 7. 架构约束

### 7.1 分层

1. ScreenTraceCore：项目模型、事件、算法、时间线与可移植逻辑；
2. ScreenTraceMac：ScreenCaptureKit、AVFoundation、AppKit、SwiftUI 与 macOS 权限；
3. Capture Runtime：原始媒体、事件、分片和恢复；
4. Draft Engine：运镜、光标、音频、字幕与整理建议；
5. Renderer：预览与导出共用组合逻辑；
6. Library：索引、搜索、项目打开和兼容迁移。

### 7.2 不可妥协约束

- raw 永不被编辑器覆盖；
- 录制中持续原子写入可恢复状态；
- 项目 schema 有版本、拒绝未知写入、支持旧版只读或迁移；
- 预览和导出不维护两套效果语义；
- 捕获链不能等待 OCR、转写、整理或生成式模型；
- 日志只允许白名单字段，不记录路径正文、转写正文或普通按键；
- macOS 原生体验不为未来 Windows 共享 UI 让步；
- Rust worker 和跨平台适配只有在提供明确收益时启用。

### 7.3 长期开放边界

推荐公开：

- .screentrace 格式说明；
- schema、兼容样本和迁移工具；
- 只读 SDK 与 edit-plan 工具；
- 隐私与安全约束。

在许可证未决定前，不能把完整产品宣传为开源。

## 8. 质量指标

### 8.1 性能

| 指标 | 1.0 目标 |
|---|---|
| 快捷键到捕获层出现 | P95 目标 150ms 内，按基线硬件记录 |
| 截图到剪贴板可用 | P95 目标 300ms 左右 |
| 截图到 Quick Access 可操作 | P95 目标 500ms 内 |
| 停止录屏到原始视频可播放 | 典型会话目标 1 秒内 |
| 捕获 Agent 空闲资源 | 无可感知持续 CPU 与能耗 |
| 自动草稿 | 后台生成，不阻塞原始素材和编辑器打开 |

所有性能报告必须记录硬件、系统、分辨率、FPS、素材时长和构建类型。

2026-08-11 首轮卡顿证据与处理：

- 区域选取拖动事件耗时 P95 低于 `1 ms`，卡顿主因不是选框几何；窗口吸附目标准备曾出现 `236–731 ms`，现已在 App 启动时以低优先级预热、短时缓存并在后台刷新，捕获层不等待枚举完成；
- 屏迹库卡片过去会在 SwiftUI `body` 中同步读取每张截图，现改为后台映射读取与内存缩略图缓存；
- 后续真机验收需要重新采集快捷键到捕获层、首个吸附目标和资料库首屏/滚动数据，不能只以单元测试代替体感结论。

### 8.2 正确性与可靠性

- 连续 100 次区域截图、剪贴板和 Quick Access 无失败；
- 支持矩阵内长截图成功率达到发布门槛，失败不伪装成功；
- 一小时录屏无崩溃、无不可接受音画漂移；
- 强退、设备中断、磁盘不足和系统流中断后已有分片可恢复；
- 发布回归项目全部导出成功，且 raw 哈希不变；
- Crash-free sessions 在公开 Beta 中目标不低于 99.9%；
- 项目索引损坏后可从项目包重建。

### 8.3 自动成片品质

- 黄金一分钟脚本中，无意义镜头中位数不超过 1 次/分钟；
- 80% 黄金脚本的自动草稿只需不超过两处镜头修改；
- 同一黄金项目的克制、适中、积极三档在镜头数量、停留和倍率上符合定义，且不会破坏点击聚类；
- “按点击重新生成”只重算自动镜头，手动和锁定镜头的内容、顺序与源时码保持不变；
- 一分钟项目的镜头计划重算不阻塞主线程，目标在 300 ms 内提交新计划，媒体预览继续异步生成；
- 光标平滑不落后真实点击，不漂移到错误控件；
- `0 ms` 光标平滑可还原原始路径；其他档位的点击帧与真实点击位置保持一致；
- 运动模糊只随镜头速度出现，静止画面、字幕、光标和点击目标保持可读；
- 自然成片与聚焦演示在盲测中能被用户正确理解；
- 与 Screen Studio、Recordly/OpenScreen 参考输出做匿名盲测；
- 免费开源基线至少打平，目标在“可直接分享”上形成明显优势；
- 任何竞品盲测只比较用户价值，不复制品牌素材或受限代码。

### 8.4 产品验证

Public Beta 前建立目标用户小组，观察：

- 首次安装到第一次成功截图/录屏的时间；
- 第二周仍使用屏迹的人数；
- 每周使用截图和录屏两种能力的比例；
- 自动草稿直接导出或只做轻微修改的比例；
- 用户卸载原有截图/录屏工具的真实原因；
- 最常见失败和放弃步骤。

建议决策目标：

- 新用户无需说明完成截图发送和窗口录屏导出；
- 目标用户第二周留存达到可持续迭代水平；
- 统一工作台带来的双功能使用率得到验证；
- 付费意愿来自节省时间和结果品质，而不是功能列表。

#### 2026-08-13 PCM 分片与强杀恢复执行记录

- 根因验证：并行运行第二个 `AVAssetWriter` 音频会话会令当前 macOS 真机的 ScreenCaptureKit 系统音频在约 1.25 秒后停止；改为把原生双声道 PCM 写入原子 CAF 分片，正常停止时无重编码合入最终 MP4。

## 12. 商业与许可证决策

### 12.1 必须在 G5 前决定

| 决策 | 需要回答 |
|---|---|
| LICENSE | 完整 App、Core、格式和 SDK 分别采用什么许可 |
| 商业模式 | 买断、买断加更新期、双许可或订阅的边界 |
| 云成本 | 哪些未来功能产生持续托管成本 |
| 商业使用 | 个人免费、商业许可和贡献者协议如何定义 |
| 品牌 | 最终中文名、英文名、图标和 Bundle 身份 |

### 12.2 推荐方向

- .screentrace 格式、schema、只读 SDK 和迁移工具保持开放；
- 完整 App 选择 AGPL + 商业双许可，或开放 Core、商业化原生壳；
- 本地核心能力优先采用买断或买断加更新期；
- 只有云分享、团队或托管 AI 产生持续成本时才引入订阅；
- Public Beta 可以免费验证，但不能用“永久免费”阻断可持续维护。

最终方案需要单独的架构/商业决策记录，不在本规格中替用户做不可逆决定。

## 13. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 再次回到功能清单竞争 | 1.0 失焦、品质下降 | 新需求必须映射黄金闭环和指标 |
| 自动运镜存在但观感不佳 | 核心付费理由失效 | 长流程、调参数据和匿名盲测 |
| Quick Access 缺最后一步 | 无法成为日用截图工具 | 拖出和反馈列为 G1 阻断 |
| 录屏异常导致素材丢失 | 信任不可恢复 | 分片、原子状态、故障注入和恢复 |
| 预览与导出不一致 | 用户无法信任编辑器 | 同一组合器、真实媒体像素回归 |
| 极致玻璃影响可读性或性能 | 漂亮但不好用 | 三层材质、设计令牌和降级路径 |
| AI 文案超前于实现 | 预期落差与隐私担忧 | 使用“本地智能整理”，能力逐项说明 |
| 开源边界模糊 | 法律和商业风险 | G5 前完成许可证与依赖审计 |
| 过早 Windows 迁移 | macOS 品质被稀释 | 只保留接口，不进入 1.0 执行 |
| 测试数字和状态文档不一致 | 信用损失 | 发布前自动生成能力与测试快照 |

## 14. Definition of Done

任何用户可见能力只有满足以下条件才能标为完成：

1. 需求 ID 与黄金闭环明确；
2. 核心逻辑自动测试通过；
3. 真实媒体或项目兼容测试通过；
4. 原生 UI 快照通过；
5. 安装版真机主路径通过；
6. 相关异常与恢复路径通过；
7. 性能没有超过预算；
8. VoiceOver、键盘、降低透明度和减少动态效果得到验证；
9. 隐私字段和日志经过审查；
10. README、总计划、竞品矩阵或用户指南同步更新；
11. 原始素材不被破坏；
12. 发布主张具有对应证据等级。

单元测试通过、代码存在或界面能点，都不足以单独宣布功能完成。
