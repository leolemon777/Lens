# 屏迹「苹果式丝滑 2.0」SPEC / CODE 执行计划

> 版本：2.0 Draft 1  
> 日期：2026-08-12  
> 当前范围：macOS 首版；Windows 迁移暂缓  
> 北极星：任何一次点击都有即时、连续、可信的反馈；智能能力安静地完成，不把等待转嫁给用户。

## 1. 为什么还会觉得“不够丝滑”

现有真机基线已经达到约 60.06 FPS、P95 16.67 ms、0 丢帧，原始录屏安全收尾约 72.48 ms。因此下一阶段不再把问题简单归因于“帧率低”，而是处理四类感知延迟：

1. 录屏停止后，原片已经可用，但编辑器仍等待智能预览渲染，造成“卡在分析”的错觉。
2. 自动运镜响应每次点击，镜头移动过频；运动模糊过强时，即使帧率稳定也会显得拖沓、眩晕。
3. 浮标、计时、音量和编辑器状态更新频率不统一，SwiftUI 无效刷新会与录屏争夺主线程。
4. 普通用户第一眼看到的控制项过多，操作路径和视觉层级比同类成熟产品更重。

## 2. 产品原则

- **先可用，后变美**：原片落盘后立即播放；自动运镜、字幕、降噪和美化渐进增强。
- **静止优先**：没有明确意图时镜头保持不动；少一次运镜比多一次错误运镜更高级。
- **连续优先**：播放位置、窗口和编辑状态不因后台结果完成而跳变。
- **真实状态**：不使用无限“分析中”；明确区分“原片可看 / 智能版生成中 / 智能版已就绪 / 可重试”。
- **可撤销、非破坏**：原始视频、音轨、事件轨始终保留，所有效果只写编辑计划和派生预览。
- **默认即成片**：默认 1.6×，点击反馈开启，前置摄像头关闭，高级参数折叠。

## 3. 分阶段执行

### P0 — 录完立刻可看（当前执行）

目标：消除最明显的“停止后卡住”体验。

- [x] 原始视频安全收尾后立即打开编辑器，不等待智能预览。
- [x] 编辑器先加载原片，保留完整播放、拖动和编辑能力。
- [x] 自动成片在独立后台任务中运行；转写继续在其后按设置执行。
- [x] 智能预览完成后渐进接管播放器，不重置窗口、播放头和选中状态。
- [x] 增加陈旧结果保护：用户已修改计划或正在重新生成时，不采用旧的后台预览。
- [x] 资料库状态改为“智能处理中”，说明原片并未被锁住。
- [x] 增加单元测试，覆盖后台结果可采用、脏编辑拒绝采用、旧计划拒绝采用。

验收：

- 从 `recording.stop()` 返回到编辑器展示，P95 ≤ 300 ms。
- 智能预览耗时不阻塞主窗口，不出现模态等待页。
- 后台处理期间可播放原片、拖动时间线并开始编辑。
- 旧渲染结果不会覆盖用户的新参数。

### P1 — 低运动自动运镜

目标：从“跟着每一次点击跑”升级为“理解用户演示意图”。

- [x] 自然成片默认倍率锁定为 1.6×；手动倍率与自动运镜解耦。
- [x] 建立点击聚类：同一区域短时间连续操作合并为一个镜头意图。
- [x] 建立安全区：光标停留在焦点安全区内不移动镜头。
- [x] 建立迟滞：进入和离开焦点使用不同阈值，避免边缘来回抖动。
- [x] 滚动保护：连续滚动期间锁定构图，滚动结束后再判断是否重构图。
- [x] 最短停留与返回节奏：进入、停留、返回分别限制速度和持续时间。
- [x] “平滑”模式以少动为主；“聚焦演示”允许更积极但仍受眩晕预算约束。
- [x] 调倍率后只重新生成相机计划，不关闭自动运镜、不丢点击事件。

建议默认节奏：

| 项目 | 平滑（自然成片） | 聚焦演示 |
|---|---:|---:|
| 默认倍率 | 1.6× | 1.8× |
| 同区点击合并窗口 | 1.0 s | 0.7 s |
| 最短镜头停留 | 1.4 s | 1.0 s |
| 返回全景空闲时间 | 2.4 s | 1.8 s |
| 每分钟建议运镜上限 | 6 次 | 10 次 |

验收：10 分钟浏览器演示中，不出现一次点击一次推拉；同区域连续点击保持构图；倍率变化后仍生成非基线相机关键帧。

### P1 — 运动模糊与视觉稳定

- [x] 模糊只覆盖镜头真正移动的区间，不对静止画面施加残留模糊。
- [x] 模糊强度同时受位移、速度和缩放变化约束，设置全局“眩晕预算”。
- [x] 自然成片默认值下优先清晰，快速长距离移动才短暂增加模糊。
- [x] 点击波纹与镜头移动错峰，避免同一帧发生两次强视觉刺激。
- [x] 导出与编辑器预览使用同一时间采样和插值函数。

验收：静止段像素稳定；全屏明显模糊占比 < 5%；预览和导出关键帧位置一致。

### P1 — 浮标与编辑器“轻量化”

- [x] 录屏浮标保持跨窗口置顶，可由用户手动隐藏并随时恢复。
- [x] 音量与性能采样和界面刷新解耦；UI 以 15–20 Hz 节流显示，录制仍维持 60 FPS。
- [x] 未发生变化的状态不触发视图发布。
- [x] 编辑器默认只展示“画面、运镜、光标与点击、声音”四个入口；高级参数折叠。
- [x] 玻璃层减少大面积实时模糊叠加，使用材质层复用、连续圆角和统一弹簧曲线。
- [ ] 所有耗时按钮先切换本地状态，再发起后台任务。

验收：后台录制 CPU 和当前基线持平或更低；浮标拖动与跨 App 切换无明显停顿；控制动作首帧反馈 < 100 ms。

### P2 — 成片质量与长期可用性

- [ ] 点击波纹、平滑光标、自动运镜、画布、摄像头、字幕、降噪逐项做预览/导出一致性测试。
- [ ] 建立 Safari、Finder、Xcode、Office/普通 App 四类固定录制脚本。
- [ ] 建立 30 秒、5 分钟、30 分钟三档录屏稳定性测试。
- [ ] 增加安装覆盖、权限恢复、崩溃恢复、磁盘不足、睡眠唤醒验收。
- [ ] 完成 Release 构建、签名检查、隐私说明和 macOS Beta 打包。

## 4. 代码落点

| 目标 | 主要代码 | 实现方式 |
|---|---|---|
| 原片立即打开 | `AppDelegate.stopRecording` | 从同步等待改为渐进式后台处理 |
| 后台预览安全接管 | `VideoEditorWindowController` | 同包校验、计划版本校验、脏状态保护 |
| 结果采用策略 | `VideoEditorModel` | 纯逻辑判定并增加单元测试 |
| 真实资料库状态 | `TraceLibraryView` | “智能处理中”，编辑入口保持可用 |
| 低运动镜头 | `AutoCameraPlanner` | 聚类、安全区、迟滞、滚动锁、运动预算 |
| 插值与模糊一致 | `EffectTimeline` / `AutoPreviewRenderer` | 单一时间函数、速度约束模糊 |
| 浮标刷新节流 | `RecordingControlWindowController` / `RecordingControlView` | 采样与发布分层、值变化去重 |
| 性能回归 | `Tests` / `Scripts` | 固定场景、帧间隔、CPU、状态延迟报告 |

## 5. 发布阻断指标

以下任一项不通过，macOS Beta 不发布：

- 录制实测平均帧率 < 58 FPS 或 P95 帧间隔 > 20 ms。
- 停止后原片编辑器 P95 展示时间 > 300 ms（不含系统写盘时间）。
- 任何后台结果覆盖新编辑、丢失原片/音轨/事件轨。
- 调整倍率后自动运镜消失。
- 预览与导出在镜头、点击、字幕或画布上出现可见不一致。
- 30 分钟录制中断、浮标失联、暂停继续错时或导出失败。

## 6. 执行顺序与当前状态

1. **P0 渐进预览**：代码、自动化、安装包和真机计时验收完成。
2. **P1 低运动运镜**：点击聚类、安全区、迟滞、滚动锁和点击前置运镜完成。
3. **P1 模糊预算与预览/导出统一**：完成。
4. **P1 浮标和编辑器刷新治理**：完成。
5. **P2 全量自动化 + Release + 真机端到端**：本轮验收完成；用户确认丝滑度、流畅度与成片效果均达标。更长耐久测试归入 Beta 发布工程。

每一阶段都必须完成“代码、测试、Release 构建、真机样片”四件套，再进入下一阶段；不以控件已经出现作为完成功能的标准。
