# 屏迹核心工作进程协议 v0.1

日期：2026-08-09  
状态：Swift 协议、帧编解码器与 stdio 运行时适配器已落地；Rust worker 尚未实现

## 目标

定义 macOS 原生壳、未来 Rust 共享核心和 Windows 平台层之间的最小稳定边界。当前不把捕获、权限、原生 UI 或 AVFoundation/ScreenCaptureKit 塞入共享核心。

## 传输

- 每条消息为 `4 字节大端无符号长度 + UTF-8 JSON`；
- 单帧上限 1 MiB，在分配或 JSON 解码前拒绝超限声明；
- 解码器支持任意分片输入和单次输入多帧；
- 当前仅定义 stdio/pipe 可共用帧，具体 macOS XPC 或 Windows named pipe 适配器后续实现。
- Swift 运行时只启动显式传入且可执行的文件，不拼接 shell 命令；默认握手超时 2 秒，stdout 连同帧头不得超过 1 MiB + 4 字节，stderr 只限量排空且不进入结果或日志。

## 握手

Client 先发送 `CoreWorkerHandshakeRequest`：

- `protocolVersion`：当前为 `1`；
- `requestID`：UUID，必须由响应原样返回；
- `clientName`：客户端实现名；
- `requestedCapabilities`：去重、排序后的能力列表。

Worker 回复 `CoreWorkerHandshakeResponse`：

- 同一 `protocolVersion` 和 `requestID`；
- `workerVersion`；
- `supportedCapabilities`。

不兼容或无法处理时回复 `CoreWorkerErrorResponse`，错误只使用稳定代码，不夹带项目正文、路径或媒体数据。

## 能力 v1

- `projectSchema`：开放项目格式校验/迁移；
- `autoCameraPlanning`：事件轨到运镜计划；
- `captionPlanning`：转写到字幕计划；
- `localOrganization`：本地确定性整理。

能力名只用于握手协商，不表示当前已有 Rust 实现。Swift 仍是生产主链，直到对应 worker 通过一致性测试和故障回退验收。

## 安全与回退

- 输入先做帧长校验，再做 JSON/schema 校验；
- worker 不直接获得系统权限或 UI 引用；
- worker 超时、崩溃、协议不兼容时，必须回退当前 Swift 实现；
- Swift 适配器把未配置、不可执行、启动失败、超时、非零退出、超限输出、畸形响应、协议/请求不匹配和 worker 稳定错误码收敛为无路径、无正文的回退原因；只有协议版本与请求 ID 同时匹配时才接受能力交集；
- 引入 Rust 后，每个能力必须使用同一输入跑 Swift/Rust 黄金一致性测试。
