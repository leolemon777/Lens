## HuaStudio 实测

### 通过项

- 单窗口选择器能看到并选择被遮挡的 Edge 窗口。
- 系统声音默认开启；前置摄像头默认关闭。
- 录制浮标跨窗口显示，暂停、继续、停止均可用。
- 编辑器提供画布、自动运镜、光标、声音等面板。
- 默认运镜倍率为 1.6×，运动模糊为 65%。
- 导出支持横屏、竖屏、微信 720p、1080p、720p、原始分辨率及可选 HEVC。

### 失败 / 风险项

- 本次 70.37 秒窗口录屏的 `track.json` 中 `clicks` 为空，`project.json` 中 `zoomSegs` 为空。即使点击“按点击重新生成”，也只出现成功提示，没有生成运镜片段。
- 光标轨只有 19 个点，而且主要集中在约 54 秒附近；不足以重绘完整 70 秒光标路径。
- 导出后停留在编辑器时仍持续占用约 68%–101% CPU，RSS 约 383–395 MB，后台空转明显偏高。

### 导出媒体

- H.264 + AAC，1868×1080。
- 70.37 秒，36 MB，约 4.29 Mbps。
- 名义帧率约 57.68 fps。

## ScreenTrace `/Applications` 安装旧版实测

### 通过项

- 区域、窗口、当前屏幕三种来源可选。
- 窗口选择器能看到并选择 Edge。
- 自然成片、聚焦演示、教学讲解、原始录制四种模式可选。
- 30 / 60 FPS、系统声音、麦克风、自动转写可选；摄像头默认关闭。
- 常驻浮标、隐藏、暂停、继续、停止可用。
- 单个删除与全部删除入口都已存在。

### 失败 / 风险项

- 这不是工作区最新版本：安装版二进制时间为 2026-08-11 11:58，工作区最新构建为 2026-08-12 00:33；哈希和签名均不同。
- 本次 68 秒样本的 `pointer.jsonl`、`clicks.jsonl`、`keyboard.jsonl`、`windows.jsonl` 全部为 0 行。
- 自动编辑计划只有一个 1× baseline 镜头，光标关键帧和点击波纹都为空。因此 UI 显示“自动运镜 / 跟随光标 / 点击反馈”开启，但成片仍是普通录屏。
- 自动倍率仍显示 1.28×，不是当前源码要求的 1.60×，再次证明是旧构建。

## ScreenTrace 工作区最新构建实测

### 通过项

- 系统权限页显示屏幕、麦克风、摄像头、语音识别、辅助功能全部已允许。
- 60 FPS 窗口录制流程、常驻浮标、暂停、继续、停止、后台生成和编辑器均可完成。
- 实际项目文件捕获到：161 个光标事件、8 个点击事件、1 个窗口事件。
- 自动编辑计划实际生成：11 个镜头关键帧、147 个平滑光标关键帧、3 个点击波纹。
- 点击聚焦关键帧为 1.60×，并包含 pointerFollow、clickFocus、clickHold、returnToOverview 等完整镜头阶段。
- 导出的自动预览逐帧检查可见 1.6× 推近、光标重绘、双环点击波纹与回到全景；这条链路在最新构建中是真正生效的。
- 后台生成完成后约 0.9% CPU。最新构建录制阶段与旧版、渲染任务有重叠，本轮没有得到足够干净的独立录制 CPU 样本；旧安装版录制阶段曾抽样约 9%。

### 失败 / 风险项

- UI 和 manifest 都记录为 60 FPS，但原始 `screen.mp4` 的名义帧率约 29.97 fps，自动预览约 29.99 fps。当前“60 FPS”并未在最终媒体层兑现，是需要优先修复或重新定义文案的真实问题。
- 镜头回退阶段的运动模糊在抽帧中非常强，整个画面会短暂明显糊成一片；这可能正是用户感到“不够苹果式丝滑”的来源之一。
- 同时运行 `/Applications` 旧版和 `Build` 新版会造成同 bundle ID 的窗口、权限和文件观察混淆，不应作为正常用户环境。

### 媒体信息

- 原始轨：H.264，2040×1380，178.11 秒，48 MB，约 2.26 Mbps，约 29.97 fps。
- 自动预览：H.264，2040×1380，178.12 秒，53 MB，约 2.48 Mbps，约 29.99 fps。

## QuickTime / macOS 截屏工具栏实测

- 提供整屏、所选窗口、所选区域录制。
- 选项包括保存位置、5 / 10 秒倒计时、麦克风、显示浮动缩略图、记住上次选择、显示鼠标点按。
- 录制启动和停止控制可用，录制进程占用很低。
- 不提供暂停 / 继续、独立光标轨、自动运镜、平滑光标、点击波纹参数、背景画布、字幕校对或非破坏时间线。
- 当前保存目的地设为 QuickTime Player；本次短样本结束后未落成独立文件，因此只完成了录制 UI 与进程级验证，没有纳入成片媒体对比。

## 结论与优先级

1. **先统一安装版本。** 当前用户打开的 `/Applications/ScreenTrace.app` 是旧构建，它会直接复现“没有自动运镜、没有点击特效、倍率不是 1.6×”。
2. **最新构建的事件与成片链路已经真实工作。** 不再是只有 UI 开关；项目文件和抽帧都证明自动运镜、光标重绘、点击波纹有效。
3. **最高优先级缺陷是 60 FPS 未兑现。** UI、manifest 与真实媒体不一致，必须修复编码链路或改为准确的动态帧率说明。
4. **第二优先级是运动模糊过强。** 转场中段整帧模糊明显，需要降低强度、缩短模糊持续时间并用速度曲线约束峰值。
5. **资源占用方面 ScreenTrace 最新构建在任务完成后更干净。** HuaStudio 在编辑器空转时持续高 CPU；ScreenTrace 生成完成后能回落到约 1%。下一轮仍应在只运行单一构建时补一组录制阶段的干净采样。
6. **系统 QuickTime 仍是可靠的基础兜底。** 但它不具备本项目的智能镜头、可编辑事件轨和成片能力。
