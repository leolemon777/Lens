结果：生成 2.1 MiB DMG、2.0 MiB App zip 和 4.0 MiB dSYM zip；DMG 两次 `hdiutil verify` 通过，挂载后 App 的 ad-hoc 签名、Info.plist 和 Applications 链接通过。当次 SHA-256 依次为 DMG `322f86211d2d83ffaf330c46ce742216042d9ed613744548095405c81b7f211f`、App zip `fbeeba9a2d1f0ede722a99b4ff98f37a9c21ff6fe6fe2cdfe3e03861f9111a82`、dSYM zip `e3450c0849716df05a0e5ae8add7c41ad7cbd9dd9b7fdb701e97a2465ab9ab06`，校验和文件反向复核三项均为 `OK`。打包链现另生成机器可读 `release.json`，记录版本、最低系统、Git commit/工作区、Mach-O UUID、签名、Team ID、公证 request ID 和三类制品尺寸/摘要，并把该清单纳入 SHA-256 文件。当前签名明确为 `ad-hoc`、无 TeamIdentifier，未提供公证 profile，不等同于可公开分发的 Beta。

Finder 实际预览 `Build/ScreenTrace.app` 后曾写入 `com.apple.FinderInfo` 与用户标签，旧打包逻辑复现 `resource fork, Finder information, or similar detritus not allowed` 并拒绝重签名。构建脚本改为先校验固定生成路径再完整重建 App；同一台机器重新执行 Release 构建、严格验签与 DMG 打包全部通过，不再继承 Finder 污染或旧签名资源。

独立发布验收器另从 `release.json` 出发，不复用打包过程中的临时状态：反查四项 SHA、三类制品尺寸、Git commit/clean、版本、最低系统、App/dSYM UUID、图标、App zip 布局、只读 DMG、Applications 链接和严格签名结构。`--development` 允许当前 ad-hoc/未公证包完成结构验证；公开模式必须在同一结构检查后继续满足许可证、Developer ID、Team ID、App/DMG 公证 Accepted、Staple 与 Gatekeeper，当前包应明确失败于这些尚未提供的发布资格。

正式 App 图标主图固定为 1024×1024 不透明 RGB PNG；已人工复核 128、32 和 16 像素辨识度。构建脚本从唯一主图生成十档标准 iconset 与 `AppIcon.icns`，公开源码审计只允许该固定路径与 SHA-256 的 PNG。Release App 仍需复核 Info.plist 引用、资源非空和签名后完整性。

离线符号化脚本已通过两类实测：本机旧 `.ips` 与当前 dSYM UUID 不一致时以状态 67 拒绝；使用当前 UUID/base/image offset 构造的合成 `.ips` 成功输出 `CaptionCuePlanner.swift:245` 的 Swift 符号化帧。
